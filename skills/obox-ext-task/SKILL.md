# obox 扩展开发 · 第 6 步：任务卡拆分

## 职责

**做**：把 spec delta + `design.md` 拆成可派发、不互相踩文件的任务卡，定出并行组。
**不做**：不写代码，不改 spec / design，不替用户放宽验收标准。

公共约定见 `docs/extension-workflow.md`（§七 任务卡与并行、§五 门禁、§十 提问规范），**逐条照做**。

## 输入与前置检查

| 输入       | 路径                                                      |
| ---------- | --------------------------------------------------------- |
| spec delta | `openspec/changes/<change-id>/specs/<capability>/spec.md` |
| 设计文档   | `openspec/changes/<change-id>/design.md`                  |
| 校验结论   | `openspec/changes/<change-id>/notes/validation.md`        |

开工前确认，**不过就先修，不得继续**：

1. `notes/validation.md` 存在，且没有未处置的严重问题——有则回 `validation` 的门禁追问。
2. `design.md` 含可落地的文件布局（拆卡要按它划所有权）。
3. 门槛命令已确定（宿主动作看 `package.json` scripts；扩展工程看其 `package.json` 的 `build` / `pack`）。

## 步骤

### 1. 按设计文档的落点列改动清单

逐个列出要新增/修改的**文件级**落点（`manifest.json`、`index.js`、`lib/**`、`src/**`、`test/**`、`ui/**`、`docs/**`）。

**完成判据**：清单覆盖 `design.md` 提到的每个落点；每个落点都是具体文件或目录，不写"相关模块"这类模糊项。

### 2. 定卡并分配文件所有权

一张卡 = 一句话可验收的结果。**硬规则：同一个文件只能归一张卡**，任何重叠都必须当场消解（合并两卡，或把公共文件单独成卡排在前面）。

**完成判据**：把每张卡的文件清单两两求交集，**交集全为空**；交集不为空时已合并或已单独成卡。

### 3. 写卡

路径 `openspec/changes/<change-id>/notes/tasks/<nn>-<slug>.md`（`nn` 两位数字，`slug` 英文 kebab-case）。**字段固定，一个不漏**：

| 字段       | 内容                                           |
| ---------- | ---------------------------------------------- |
| 目标       | 一句话可验收的结果                             |
| 输入       | spec delta 与 `design.md` 的相关小节（给锚点） |
| 文件所有权 | 允许改动的文件清单（同一文件不属二卡）         |
| 验收命令   | 该卡对应的门槛命令与期望结果                   |
| 依赖与阻塞 | 必须在其之前完成的卡                           |
| 并行组     | 组号                                           |

**完成判据**：每张卡六个字段齐全；输入给的是锚点而不是"见 design"。

**负向自检怎么写**（否则会与"同一文件只能归一张卡"打架）：负向用例（"非法输入应被拒"、"越权应报错"）优先用**不改实现**的方式表达——喂非法输入 / 越界参数、`assert.throws`、断言返回错误码；**不要**写成"临时把某处改坏再跑一遍"。确需临时改实现才能验的，卡里必须写明两条：**由该文件所有权卡的卡主授权**，且**还原后 `git status` 无残留**（`git status --porcelain=v1` 与本卡开工前一致）。

### 4. 划并行组

**同组可同时开工，跨组串行**。依据三点：文件所有权不重叠、无数据/接口依赖、验收命令互不干扰。

**完成判据**：每组内任取两卡，都满足"文件不重叠 + 无依赖"；跨组依赖已写进卡的"依赖与阻塞"。

### 5. 克制卡的数量

能**一张卡做完的不要拆两张**。拆分的唯一理由是"需要并行"或"验收命令不同"。

**完成判据**：每张卡都说得出一条拆它的理由；说不出就并回相邻卡。

### 6. 写 `tasks.md`

官方格式：`# Tasks` → `## N. <组名>` 与组文件所有权 → `- [ ] N.M <任务>`（一卡一项，自带验证方式）。

**完成判据**：条数与任务卡一一对应，编号无跳号；每条都带验证方式。

### 7. 门禁

见下。

## 产物与路径

- `openspec/changes/<change-id>/notes/tasks/<nn>-<slug>.md`（任务卡）
- `openspec/changes/<change-id>/tasks.md`（官方格式任务清单）

## 门禁

用 `ask_user_question` 问「本步产出是否符合要求？」：

1. **通过，自动进入 `obox-ext-dev`（推荐）** —— 下一步读 `skills/obox-ext-dev/SKILL.md` 并照做，按卡派子代理实现（同组并行、跨组串行），只写代码不提交。
2. **部分修改后重跑本步** —— 用户说明要改什么（例如合并某两卡）。
3. **回到上一步 `obox-ext-validation`** —— 回退并重做规格校验。
4. **暂停** —— 用户先人工检查。

被选 1 时**读取 `skills/obox-ext-dev/SKILL.md` 并照做**，不依赖 Skill 工具。

## 完成判据

- 任务卡字段固定齐全，文件所有权两两无交集；
- 并行组有明确理由，跨组依赖已登记；
- `tasks.md` 与任务卡一一对应；
- 门禁问过并拿到用户选择。
