# 验收判定（截图 + 读图）

判定方式（按 design D-6 的降级条款）：**没有**可调用的 Nemotron 3.5 Super VL 端点，
因此判定由"助手直接读图 + 关键日志交叉验证"完成；每轮记录用的是哪种判定，不冒称用过 VL 模型。

## 第 1 轮（宿主侧修复生效，pet 未改）

| # | 场景 | 判定 | 依据 |
| --- | --- | --- | --- |
| 1 | 宠物悬停面板 | ❌ 不通过 | `pet-hover-after.png`：面板容器出现（可见白色圆角描边），**底色仍透明**。日志证明 token 已送进 iframe（`[AppWindow] 下发主题 … 25 个 token`），但 pet 页面不消费。 |
| 2 | 拖动 + 点击 | ✅ 通过 | `pet-drag-after.png`：位置随拖拽改变；出现互动气泡「咕嘟咕嘟～被摸摸好舒服！」 |
| 3 | 鼠标穿透解除 | ✅ 通过 | 穿透时收不到点击；本轮点击/拖动均生效 |
| 4 | webapp `ui.appMessage` 超时 | ✅ 通过 | `[host] 渲染侧入站：t=req method=ui.appMessage` → `完成 … 0–1ms`，超时文案消失 |

## 第 2 轮（pet 消费 `obox-theme` 后）

| # | 场景 | 判定 | 依据 |
| --- | --- | --- | --- |
| 1 | 宠物悬停面板 | ✅ **通过** | `pet-panel-after.png`：面板**有深色背景**、显示等级名「初次见面」、两枚互动图标（喂食/洗澡）与关闭按钮；不再是"正在连接宠物状态…" |
| 2 | 点击 / 摸头 | ✅ 通过 | 气泡「刚摸过啦，让我缓一缓~」（冷却文本，说明点击与冷却都生效） |
| 3 | 拖动 | ✅ 通过 | 第 1 轮 `pet-drag-after.png`，位置随拖拽改变 |
| 4 | 鼠标穿透 | ✅ 通过 | 悬停出现面板、点击有反馈（穿透时两者都不可能） |
| 5 | webapp 超时 | ✅ 通过 | 同上，`ui.appMessage` 毫秒级回包 |

**结论：三项用户可见问题全部闭环**——① webapp 的 `ui.appMessage` 超时；② 宠物面板透明；
③ 宠物鼠标穿透 / 拖不动 / 面板"正在连接"。

## 判定方式的局限（如实登记）

- 视觉判定是"助手读图"，不是用户指定的 Nemotron 3.5 Super VL；若该模型可用，应重跑本节并在
  此处替换为模型输出。
- 截图来自**本地构建**（`npm run start`，与安装版同一 userData、同一批扩展），不是安装包；
  安装包的行为一致性由"同一份 `out/` 与同一 userData"保证，但仍建议用户在发布前亲自确认。
