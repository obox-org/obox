# 渲染进程扩展宿主

扩展宿主（Cordis 运行时）跑在渲染进程，而非独立扩展宿主进程或主进程。

VS Code 用独立进程 + RPC 承载扩展宿主，换取崩溃隔离与响应性检测；但对一个本地桌面壳应用，多进程 + 完整 RPC（握手、ack/取消、URI 转换、无响应检测）是跨进程问题的解决方案，成本远超收益。我们的扩展贡献点全是 UI（导航项、视图组件、状态栏项），渲染进程是唯一自然的位置；Node 能力（窗口控制、文件系统、应用信息）经 preload IPC 以能力服务形式暴露给扩展（`ctx.window` / `ctx.fs` 等）。

代价是失去崩溃隔离——一个扩展的运行时错误会与 UI 同进程。我们用每扩展独立的错误捕获与上报（等价 `IExtensionsStatus.runtimeErrors`）缓解，不做进程隔离。
